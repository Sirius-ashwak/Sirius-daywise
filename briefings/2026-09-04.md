## The three ideas

### 1. Cinch
**One-line pitch:** A secrets vault that never hands an AI agent a real credential — only scoped, expiring capability tokens.

**The problem:** Anyone running agents (OpenClaw, Claude Code, n8n flows) today either pastes real API keys into env vars the agent can read, or types them into a masked prompt that still resolves to the actual secret somewhere downstream. One prompt injection or one runaway tool call and that key is fully live in the wild. Platform teams running agent fleets internally have this acutely — they're the ones getting paged.

**Why now:** Masked-prompt credential entry just showed up in coding-agent harnesses this year, which proves the industry agrees plaintext-in-context is broken — but it only hides the secret from the transcript, not from the agent's actual runtime access. The primitive nobody's shipped yet is *capability-scoped, time-boxed tokens issued per tool-call*, which only became feasible now that most agent frameworks route every external call through a single tool-calling layer you can intercept.

**Mechanism:** Cinch sits between the agent framework and the outside world as a proxy. The agent never sees a real API key — it asks Cinch for "post to Slack channel #eng for the next 10 minutes," Cinch mints a scoped token good for exactly that, and logs every use. Revocation and audit are instant because nothing long-lived ever left the vault.

**First wedge:** Platform/infra teams at 50-500 person companies running internal agent automations (support bots, on-call agents, CI agents) who've already had one scare. Reach them through the OpenClaw and Claude Code plugin/marketplace ecosystems — ship as a drop-in proxy config, not a new platform to adopt.

**What kills it:** The agent frameworks themselves (Anthropic, OpenAI, LangChain) build this natively as a platform feature, since it's a thin, obvious layer once you already control the tool-calling loop — Cinch becomes a feature, not a company.

**Weirder variant:** Same broker pattern, applied to physical access — a delivery or warehouse robot requests a scoped, time-boxed "open door 4B for 90 seconds" token instead of holding a standing badge credential, so a compromised robot can't wander the building.

### 2. Amperage
**One-line pitch:** Real-time cost-per-token attribution across multi-cloud GPU fleets, built for the 200-person AI team, not the hyperscaler.

**The problem:** Nexthop AI, Etched, and Groq are all selling infrastructure at a scale only well-funded AI labs can absorb. Everyone below that tier — the mid-market company running inference across two or three GPU clouds because capacity is scarce and pricing is volatile — has no idea which feature, customer, or model call is actually burning their budget. Finance finds out at the end of the month, from an invoice, not in real time.

**Why now:** Multi-cloud GPU renting became the default this year purely because single-vendor capacity keeps running out — nobody chose fragmentation, scarcity forced it. That fragmentation is exactly what makes cost attribution hard, and it didn't exist as a problem when everyone just used one vendor's dashboard.

**Mechanism:** A lightweight sidecar sits in the inference request path (same interception point as any LLM gateway) and tags every call with the internal caller, feature flag, and customer ID, then reconciles that against the actual cloud invoice line items as they land. Output is a live dashboard plus Slack alerts when a feature's inference cost spikes past its budget — the FinOps discipline the "boring bounded workflows" crowd is already asking for, just not built yet.

**First wedge:** AI-wrapper startups (10-50 engineers) already juggling 2+ GPU cloud providers because they got capacity-rationed by their first vendor. Reach them through the same channels selling multi-cloud GPU brokering — they're already primed for the pain.

**What kills it:** The GPU clouds themselves (CoreWeave, Lambda, Crusoe) each build good-enough native cost dashboards, and multi-cloud attribution turns out to be a feature request customers make to their broker, not a reason to buy a separate tool.

**Weirder variant:** Flip it from cost observability to a billing product — "Stripe for inference-metered billing," letting AI-wrapper startups charge their own customers per-token with the same attribution data, instead of flat SaaS pricing that doesn't track their own GPU spend.

### 3. Rehearsal
**One-line pitch:** Video-world-model simulation that lets a robotics startup fail 10,000 times before touching a real robot.

**The problem:** Generalist, Arda, and Embo are all racing to put embodied AI into warehouses and factories, but every one of them still burns cash and months on physical test iteration — a robot arm has to actually knock over the box before the model learns not to. Robotics founders with $10-50M seed/Series A rounds have this acutely: they're funded enough to build a robot, not enough to break a thousand of them.

**Why now:** Embo (ex-DeepMind) raising specifically to build "world models" for robotics is the tell — generative video models got good enough this year to simulate physically plausible outcomes cheaply, which means a synthetic test environment can now be *generated on demand* for a specific robot and task instead of hand-built in a game engine.

**Mechanism:** A robotics team feeds Rehearsal their robot's spec sheet and target task (e.g., "pick items off a warehouse shelf"). Rehearsal generates thousands of synthetic video-model rollouts of that exact task under varied conditions, scores failure modes, and hands back a ranked list of edge cases to test physically — collapsing months of trial-and-error into a week of simulated rehearsal before the robot ever touches the real shelf.

**First wedge:** Seed-to-Series-A vertical robotics startups (warehouse, last-mile delivery, agriculture) who can't afford Skild-AI-scale physical test infrastructure. Reach them through robotics-specific accelerators and the same investor networks funding this wave (a16z robotics, Lux Capital).

**What kills it:** World-model fidelity isn't good enough yet for the edge cases that actually matter (unusual lighting, novel object shapes), so customers keep it as a cheap pre-filter but still do the expensive physical testing anyway — Rehearsal becomes a nice-to-have, not a replacement.

**Weirder variant:** Point the same simulator at human processes instead of robots — simulate a retail store layout change or a call-center script change with a world model before rolling it out physically, treating "will this confuse a human" as the same class of problem as "will this confuse a robot."

## Where I might be wrong

**Rehearsal is the weakest of the three.** World-model simulation for robotics is already exactly what the best-funded players (Skild AI, Embo, and reportedly several stealth labs) are building in-house as a core capability, not something they'd buy from a startup — the wedge might not exist because the beachhead customers are also the most likely to out-build you. It needs a gut-check with an actual robotics founder on whether "we'd buy this instead of building it" is true below Series A, or whether it only holds pre-seed.

**Cinch's biggest unverified assumption** is that agent frameworks will keep tool-calling as an interceptable, single-choke-point layer rather than each vendor building bespoke credential handling that route around a third-party proxy — worth watching what Anthropic/OpenAI ship natively before betting the company on the gap staying open.

**Amperage is the most immediately buildable** and has the clearest evidence of the pain (multi-cloud fragmentation is provably happening right now), but it's also the easiest for an existing player (Datadog, or the GPU clouds themselves) to bolt on as a feature in a quarter.
